# Independent scheduled game HTTP

GameActionsService serializes character/item/crew discovery and execution using a fresh native transport and empty AuthSession cookie jar per transaction. Its collaborators are readCredentials, createTransport and injectable limits/clock/sleep; it has no WebView, CookieSource/Sink or visible HostTracker. GameCredentials stay in memory. A rule binds username and numeric character ID; owned selection and the fresh scoped profile marker are both verified.

Public discovery: discoverCharacters returns GameCharacterCatalog; discoverItems and discoverCrew require boundUsername/character and return validated public DTOs. Changing saved account, missing credentials, unsafe routes and malformed forms return bounded GameActionException codes. cancel closes the active transport; dispose prevents queued transactions and drains ownership. Auth/session/form state is never a DTO.
GameItemChoice carries GameItemOperation.use or .tune. UseItemAction persists the same operation: absent legacy JSON and constructor defaults mean use; tune emits operation=tune, explicit use is accepted and canonically omitted. A present null, unknown or non-string operation rejects invalidAction. Instruments are offered as tune choices; unsupported wear/discard controls, ambiguous rows, disabled controls and missing hidden state remain ineligible.

GameActionLimits default to120s total,20s per request,2097152 decoded UTF8 bytes and750ms cooldown after every completed/failed request, including between transactions. Cancellation closes IO before returning and guards each later request; a response arriving late cannot start another request. Tests can provide a transport which rewrites logical Popmundo destinations to loopback, without relaxing production HTTPS/host policy.

Files: game_action_contracts.dart (ports/limits/outcome), game_actions_service.dart (gateway/auth/discovery/ownership), game_transaction.dart (deadline/abort/cooldown/private session and notification protocol), game_forms.dart (scoped identities, strict fresh forms, direct inventory rows and exact crew quotes), game_notification_signals.dart (strict envelope decoding).

Successful form controls use opt-in strictDisabledControls, including disabled fieldsets/optgroups/options, first-legend exception and foreign form ownership. Existing visible login retains default serialization. Gameplay helpers clear event fields and read live button/hidden state; no stale form is persisted. Item eligibility accepts only exact Item_Use.png (use) and Item_Tune.png (tune) basenames, including relative icon paths; discovery deduplicates the name/operation pair and the saved operation must match on every occurrence; crew prices use strict PT grammar and overflow-safe integer cents. Artist display label comes from the verified page title (optional notification counter), never the sidebar's Informações gerais link.

Notification preflight accepts an empty list or only normal Status0/Textstring signals. It seeks neutrality in at most two reads; malformed/non-neutral baseline aborts. After a possible effect, only an all-success response confirms, all-error fails; empty/normal/unknown/mixed is uncertain. Endpoint name does not imply draining.

execute now supports UseItemAction: GET fresh inventory, first eligible exact normalized-name and saved-operation row, preserved full form with image x/y=1, neutral notification preflight, exactly one gameplay POST and strict fresh outcome. Item absence returns unavailable; post-response loss/cancellation is uncertain, never retried. Explicit tune uses the same guarded full-form transaction; a legacy or default use action never tunes, and tune never falls back to use. Production credentials and authenticated HTML never enter default tests. Tests use synthetic transports/loopback; opt-in live discovery never calls execute or writes captures.

Login GET explicitly permits the actual login controls on /Default.aspx; every post-authentication route still rejects a login form. This distinction is regression-tested with synthetic real control names. Optional live diagnostics require POPMUNDO_TRACE_ROUTES=true and publish only method/host/path/status plus sanitized form action routing, never query strings or payloads.

After character selection establishes an origin, profile/target discovery/gameplay response must retain that origin; a cross-host same-path redirect is rejected before the effect, or uncertain after a possible POST. Missing/empty item form is unavailable. Authentication handover redirects remain allowed before origin establishment.

PayCrewAction now executes through the same serial gateway: verifies current artist ID, selected enabled level14..20, positive integer-cent current quote and, when present, quote<=maxCostMinor, exactly one enabled actual submit button and fresh full form. Missing artist/form/options/button, ambiguous or nonpositive price, or quote above a saved cap returns unavailable, with no payment; no replacement bonus is selected. A fresh explicit server rejection fails; unconfirmed possible payment is uncertain and never resubmitted.
A null or omitted maxCostMinor represents authorization for the configured level at the fresh valid future price. Positive caps on existing rules retain their exact behavior. Configuration may retain the verified band and maximum level20 while current bonuses are absent; execution still requires that exact enabled option, fresh positive price, matching artist and real submit button. No fallback level is paid.

GameActionsService implements ScheduledGameActionExecutor. Optional isEligible is evaluated inside the transaction queue before any transport/notice/credential read; stale occurrences fail occurrenceExpired without traffic. Optional beforeHttp is awaited under the same total deadline before fresh credentials, so admitted missing-credential attempts still issue their start notice. Notice failure is sanitized and stops credential/HTTP work; cancellation after a late notice completion cannot continue. scheduler_game_execution.dart owns coordinator routing; game_execution.dart holds endpoint transaction execution as a part of the service library.
